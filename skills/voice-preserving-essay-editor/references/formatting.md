# 排版与结构化

## 阅读层级与视觉强调

文章需要有清晰阅读层级，但结构化程度必须由内容决定。

### 标题编号

默认建议为大章节加入统一编号。

个人随笔、观影、阅读感想优先：

```markdown
## Ⅰ. 气与形
## Ⅱ. 好东西就是反着来
## Ⅲ. 强者姿态
```

方法、复盘类可使用：

```markdown
## 一、……
## 二、……
```

或：

```markdown
## 01｜……
## 02｜……
```

规则：

- 一篇文章只使用一套编号体系。
- 编号用于导航。
- 不为了"文艺"使用过度复杂符号。

---

## 加粗规则

允许使用 Markdown `**加粗**` 提升扫描阅读体验，但必须克制。

### 优先加粗

- 一个章节最关键的 1～3 个判断。
- 一个长段落真正值得停一下的核心词或核心句。
- 作者原本明显强调的概念。
- 对后文有统领作用的短判断。

### 默认不加粗

- 普通事实。
- 每段第一句。
- 所有结论句。
- 仅为了视觉节奏的词。
- 已经通过标题和语序足够突出的内容。

### 强度参考

- 短章节：0～2 处。
- 中等章节：1～3 处。
- 很长章节：通常不超过 4 处。
- 连续两个段落都大量加粗，默认视为过度。

加粗尽量是一个短语或一句短句，不要整段加粗。

---

## 结构化表达的 Scale 判断

列表、编号、表格属于可选工具，不是默认写法。

### 低结构化

适用于：

- 随笔
- 观影感想
- 阅读感想
- 情绪性思考

形式：

- 自然段
- 标题
- 少量加粗

### 中结构化

适用于：

- 有几个明确分论点的随笔
- 经验总结
- 复盘

形式：

- 标题
- 少量加粗
- 个别编号或列表

### 高结构化

适用于：

- 方法论
- 操作手册
- 知识整理
- 对比分析

形式：

- 更多列表
- 分项
- 必要表格

### 默认

个人随笔从**低结构化**开始。

只有阅读体验确实会提升，才升到中结构化。

---

## 列表与分条规则

允许使用"一二三四"或数字分条，但必须有结构理由。

可以使用：

- 多个彼此并列、边界清晰的观点。
- 一个概念下 3 个以上独立例子。
- 操作步骤。
- 原则。
- 条件。
- 分类。
- 继续写成长段会明显降低扫描效率。

不能因为"这样看起来清楚"就把连续思考硬拆成列表。

---

## 表格规则

只有信息存在明确横向比较时才考虑表格。

例如：

- A 与 B 对照。
- 多个对象共享同一组维度。
- 多个方案需要快速比较。
- 段落表达会产生大量重复。

随笔、观影感想、情绪性文字通常不需要表格。

**如果表格不能显著提高理解速度，就不用。**

---

## Markdown 默认排版

推荐结构：

```markdown
# 标题

开场 1～3 段。

## Ⅰ. 第一部分

正文……

## Ⅱ. 第二部分

正文……
```

规则：

- 通常只使用 `#` 和 `##` 两级标题。
- `##` 章节标题默认考虑加入统一编号。
- 一个自然段承载一个连续想法。
- 优先写完整段落。
- 允许少量 `**加粗**` 建立视觉锚点。
- 不靠大量一句一段制造节奏。
- 原文确实在列举多个独立对象时，可以使用列表。
- 存在明确比较维度时可以使用表格。
- Markdown 保持简约。
