# 段落与节奏

## 段落规则的演进（重要）

本文件包含三代段落规则，**后一代是对前一代的修正而非推翻**：

- **基础版**：默认写完整段落，独立短句只做少量强调。
- **v0.6 硬约束**：段落完整性升级为硬约束，限制碎片化排版。
- **v0.7（当前生效）**：保留"完整段落优先"，但取消过度机械的长段落倾向，改为"以中等长度段落为主，少量短段落做节奏变化，独立短句只做关键强调"。

**冲突时以 v0.7 为准**，但 v0.6 中关于"禁止碎片化排版"和"强制自检"的约束继续有效。

---

## 基础规则

### 默认写完整段落

**随笔的基本单位是完整段落，不是短句。**

一个自然段应承载一个完整、连续的思考。

默认处理：

- "他就是。"
- "结束。"
- "Beatrix 不是这样。"
- "我很喜欢这里。"
- "锋利、单一、往前。"
- "更少，但更重要。"

这类一句成段或短语成段，优先并回前后文。

### 禁止用空行制造虚假节奏

不为了制造：

- 高级感
- 电影感
- 文艺感
- 情绪停顿

而主动拆段。

段落之间优先靠逻辑推进，不靠：

> 短句
> 空行
> 短句
> 空行

来制造"有力量"的错觉。

### 独立短句保留条件

只有满足至少一个条件时才考虑保留：

1. 承担重要转折；
2. 是全文少数真正需要重读的判断；
3. 放回段落会明显削弱语气；
4. 位于章节结尾，并确实承担收束作用。

即使满足条件，也要控制频率。

### 强制检查

- 连续出现两个以上一句话段落，默认整改。
- 一句话段落在整篇中应非常少。
- **整篇宁可偏连续，也不要偏碎。**

## v0.6：段落完整性硬约束

此前"默认写完整段落"升级为**硬约束**，不再只是风格偏好。

### 自然段最低要求

除标题、列表、引用外：

- 一个正常自然段默认应包含 **3～6 句完整句子**。
- 如果一个段落只有 1 句或 2 句，编辑器必须检查是否可以并入前后文。
- 能并则并，不能并时才保留。
- 一个章节中连续出现两个短段落，默认视为结构失败。
- 不允许把"转折句、总结句、反问句、强调句"自动单独成段。

### 禁止的碎片化排版

以下模式默认禁止：

```markdown
一句话。

一句话。

一句话。
```

以及：

```markdown
短语。

结论。

反问。
```

也禁止为了制造节奏而写：

```markdown
当然可以。

但你要付出代价。

问题就在这里。
```

这类内容应合并成完整段落。

### 独立短句总量限制

整篇文章中：

- 独立短句通常 **不超过 3 处**。
- 每个大章节通常 **不超过 1 处**。
- 只有真正承担"强转折、章节收束、全文核心判断"的短句才可以单独成段。
- 如果一句短句只是语气强调，应优先通过逗号、分号、破折号、加粗或并入上下文处理。

### 段落优先级

编辑时的排版优先级：

1. 完整自然段
2. 段内加粗
3. 段内分号 / 破折号 / 冒号
4. 必要列表
5. 最后才是独立短句

### 强制自检

输出前必须检查：

- 是否有大量 1～2 句自然段？
- 是否有可以合并但没有合并的段落？
- 是否靠空行而不是靠逻辑组织文章？
- 是否出现"每句话都像一句金句"的 AI 化排版？
- 是否把原本连续的思考拆成了碎片？

只要答案为"是"，必须继续合并段落。

## v0.7（当前生效）：段落节奏与阅读呼吸

v0.6 的"完整段落优先"继续保留，但取消过度机械的长段落倾向。

目标是：

> **以中等长度段落为主，少量短段落做节奏变化，独立短句只做关键强调。**

### 段落长度改为"区间"而不是硬下限

除标题、列表、引用外：

- 主体自然段默认 **2～5 句**。
- 复杂论证段可到 **5～7 句**，但超过后必须检查是否应该拆分。
- 1 句段落允许存在，但必须承担明确功能。
- 2 句段落完全正常，不再默认视为结构失败。

#### 推荐分布

一篇随笔中大致可以是：

- 60%～70%：2～5 句的中等段落
- 20%～30%：1～2 句的短段落
- 0%～10%：较长论证段

不要机械计算比例，重点是形成"长短有变化"的呼吸感。

### 一段只承载一个核心推进

如果一个段落同时完成以下两件以上事情，优先拆开：

- 提出观点
- 举例
- 解释因果
- 推出结论
- 转入下一主题

理想节奏通常是：

1. 一个段落提出或展开观点；
2. 下一个段落补例子、反问或进一步推演；
3. 必要时再用一句较短的段落做收束。

这样既不会碎，也不会挤成一堵墙。

### 短段落允许，但必须有功能

1～2 句的短段落可以用于：

- 重要转折
- 章节内的局部结论
- 一个强判断
- 反问
- 从例子回到观点
- 从抽象推演切回现实

不能只是为了"有节奏"而把正常长句拆成短段。

#### 示例

不推荐：

```markdown
自由很重要。

但自由有代价。

这个代价就是不自由。
```

推荐：

```markdown
自由当然重要，但自由本身也有代价。一个人如果想真正掌控自己的时间，就必须先拥有足够强的自我管理能力。

**某种意义上，自由最大的代价，恰恰是不自由。**
```

### 独立短句规则改为"稀疏但允许"

整篇文章中：

- 独立短句不再固定限制为 3 处。
- 但通常每 **4～6 个自然段最多出现 1 个**。
- 同一章节连续出现两个独立短句，默认整改。
- 一个独立短句如果没有"转折、结论、核心判断"功能，就并回上下文。

### 阅读呼吸优先于机械完整

当一个段落超过约 120～180 个中文字符，且包含明显两个推进动作时，优先考虑拆分。

当一个段落低于约 30～40 个中文字符，且没有强强调作用时，优先考虑并回上下文。

这不是字数硬规则，而是阅读检查线。

### 小标题下的推荐节奏

一个小标题下面通常采用：

- 2～4 个主体段落
- 每段 2～5 句
- 其中可以有 1 个较短强调段
- 如有天然并列结构，再使用列表

避免两种极端：

#### 极端 A：碎片化

```markdown
一句话。

一句话。

一句话。

一句话。
```

#### 极端 B：墙式大段

```markdown
一个段落塞进五六个观点、例子、转折和总结，连续 300～500 字。
```

### 加粗与段落配合

加粗用于帮助扫描，不用于代替分段。

如果一个段落中出现两个以上完全不同的加粗判断，通常说明这个段落该拆了。

一个章节通常保留 1～3 个关键加粗点，让读者快速扫过时能够抓住脊梁。

### 节奏自检

输出前通读时，不只看逻辑，还要看"呼吸"：

- 是否连续出现 3 个以上长段？
- 是否连续出现 3 个以上短段？
- 是否有一堵明显的文字墙？
- 是否有某些段落其实包含两个不同观点？
- 是否有短句只是为了显得有力？
- 快速扫读时，能否看出每个章节最重要的 1～2 个观点？
- 阅读时是否能自然停顿，而不需要靠大量空行？

最终目标：

> **段落有骨架，短句有锋芒，长短交替，但不碎。**
